# CommLab v2.9 Trade-off Matrix

| Research question | Baselines | Primary metrics | Main v2.9 finding | Boundary |
|---|---|---|---|---|
| Which desynchronized client should receive a model repair? | age-only / static importance / task-aware | task utility, task-weighted model age, DL load | current task demand materially changes repair value at matched airtime | task-demand process is synthetic |
| How aggressively should cached models be refreshed? | eager / periodic-value / congestion-aware | version age, utility, refresh queue, bytes | eager refresh can overload the backhaul and create self-inflicted staleness; high-capacity crossover remains | simplified FIFO backhaul |
| How should FL choose clients with batteries and carbon differences? | random feasible / carbon / debt-carbon / debt+battery+carbon | excess loss, carbon, Jain fairness, infeasibility | under energy starvation every policy is feasibility-limited; once energy is available, persistent fairness and carbon conflict | carbon is a proxy, not CO2e audit |
| When should a digital twin prefetch an AI model? | reactive / blind predictive / uncertainty-gated | latency, hit rate, model backhaul, wrong prefetch | blind prediction churns the cache under uncertainty; gating retains most latency benefit with far lower transfer cost | transparent mode-state predictor |
| Which sensor deserves the shared control channel? | round-robin / Max-Age / Max-Error / control-value | closed-loop cost, information age, estimation error, excursions | lower information age can be dramatically worse for physical control than value-aware scheduling | scalar linear plant abstraction |
