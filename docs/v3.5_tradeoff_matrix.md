# v3.5 Observability Trade-off Matrix

| Feedback design | Observability | Reliability/resource behavior | Failure boundary |
|---|---|---|---|
| Outcome-only | Final protected miss | Simple; learns from actual service result | Protection hides primary failures and can lower apparent debt |
| Component telemetry | Primary radio/edge failures | Reallocates actions toward the diagnosed component | Faster/correcter attribution can still choose a poor action mix |
| Routine audits | Sparse unprotected labels | Recovers information without exposing critical tasks | Routine tasks pay the exploration cost; finite-run effect is non-monotone |
| Hybrid feedback | Telemetry plus dropout-triggered audits | Robustest when telemetry is missing | Converges to component-only behavior when telemetry is complete |
| More protection budget | More failures rescued | Lower protected miss until saturation | A larger fraction of underlying failures becomes invisible |
| Low path correlation | Duplication creates diversity | More rescue and more masking | Learned success can conceal worsening primary radio health |
| High path correlation | Little radio diversity | Duplication collapses; replicas absorb budget | Better telemetry cannot manufacture independent paths |

The matrix distinguishes information quality from policy quality: diagnosing the correct failing component is useful only if the available action has enough independent rescue value.
