## Design rule

v3.3 does not optimize each mechanism in isolation. It asks which reliability mechanism has the highest estimated downstream risk reduction **per normalized credit** under the current failure mode.

The credit system is deliberately synthetic. It exists so algorithms face a shared scarcity constraint; real metrics remain separate because a packet duplicate, a replica execution, and a 72 MB migration cannot be converted into one physical unit without a deployment-specific energy/cost model.

## No-genie boundary

The decision layer can use:

- noisy one-step edge-risk forecasts,
- current task criticality/deadline class,
- pre-transmission quality estimates for both radio paths,
- configured path correlation,
- token-bucket credit state.

It cannot use:

- realized packet success/failure,
- realized node/domain failure,
- future degradation state,
- future task arrivals.

This boundary is important because outcome-conditioned duplication or migration would silently turn a predictive policy into a genie-aided baseline.
