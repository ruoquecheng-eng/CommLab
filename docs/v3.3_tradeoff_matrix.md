# CommLab v3.3 Trade-off Matrix

| Research question | Baselines / controls | Primary metrics | Negative result / caution |
|---|---|---|---|
| Where should a finite resilience budget be spent? | reactive, radio-first, edge-first, risk-budget | weighted deadline miss, latency, credits, tx, replica, migration | more credits eventually buy redundancy faster than reliability |
| Does one redundancy mechanism work everywhere? | regime sweep over SNR and edge-risk scale | duplication / replica / migration action mix | fixed radio-first or edge-first priority is structurally regime dependent |
| Should a runtime trust a noisy edge-risk point forecast? | risk-budget vs uncertainty-gated | migration churn, MB/task, deadline reliability | gating helps under noisy forecasts but can suppress useful actions when forecasts are already good |
| What happens when radio paths become correlated? | correlation sweep | weighted miss, duplication, replica, tx/task | budget reallocation cannot recover diversity that does not exist |
| Should every available credit be spent? | high-budget risk-budget vs gated | credits spent, migration traffic, weighted miss | ungated high-budget operation enters a churn/saturation region |
| Does task criticality weighting automatically improve goal-oriented reliability? | weighted vs unweighted risk proxy | raw and task-weighted miss | no; myopic criticality weighting can lose because deadline risk is not fully captured |

## Recommended narrative

The v3.3 result is not that one heuristic dominates. The stronger conclusion is that **reliability mechanisms compete for scarce cross-layer resources**. Radio duplication is rational when radio outage dominates and the paths are diverse; cross-domain replication becomes more valuable when the radio is already good or radio redundancy is correlated; migration is worthwhile only when forecast separation is strong enough to justify state-transfer cost. A runtime that ignores uncertainty can spend more and become worse.
