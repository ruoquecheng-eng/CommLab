# v3.6 Offline Counterfactual-Evaluation Architecture

## Logged event

Each synthetic task records context, class, logging-policy protection probability, sampled protection action, and the outcome revealed by that action. Primary potential outcomes are generated before action selection but remain hidden from estimators.

Critical tasks have logging propensity exactly one for protection. This preserves the v3.5 safety rule and deliberately creates an identification boundary for targets that would remove critical protection.

## Estimators

| Estimator | Uses outcome model | Uses propensity | Primary failure mode |
|---|---:|---:|---|
| DM | yes | no | model misspecification and unsupported extrapolation |
| IPS | no | yes | large weights and high variance |
| SNIPS | no | yes | self-normalization bias under finite samples |
| DR | yes | yes | still unstable under weak overlap; not robust to support failure |
| Clipped DR | yes | yes, clipped | lower variance at the cost of clipping bias |

## Safety and support contract

The evaluator computes weighted target mass assigned to any action with zero logging probability. If this mass is nonzero, `identifiable` is false. The estimate is still exposed to show how plausible-looking extrapolation can occur, but the Dashboard displays an explicit warning.

## Temporal estimand

`recency_fraction` changes the target log window. The release separately reports value against the final 20% current regime. A full-history estimate can be accurate for the historical mixture and badly wrong for current deployment risk.

## Policy selector

Greedy selection minimizes estimated miss plus a known protection-cost proxy. The conservative heuristic requires a candidate's approximate upper objective bound to beat the baseline's approximate lower bound; otherwise it keeps the baseline. Because intervals are not dependence-robust certificates, this mode is deliberately not named certified or safe.
