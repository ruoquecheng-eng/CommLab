# v3.5 Counterfactual-Observability Architecture

## Why v3.4 feedback was incomplete

The v3.4 controller learned from the final task miss after protection. When duplication rescues a failed primary radio transmission or a cross-domain replica rescues a failed primary edge execution, the final label is success. Repeated protection therefore changes which failures remain visible to the controller.

## Paired event sequence

1. Generate primary and backup radio/edge potential failures before the policy acts.
2. Reveal stale risk estimates and the current token bucket, never realized outcomes.
3. Select zero or more eligible protection actions.
4. Compute both the unprotected base outcome and the protected final outcome.
5. Queue only the feedback authorized by the selected mode.
6. After the configured delay, update global outcome debt or component-specific debt.

The hidden unprotected outcome is recorded for evaluation only. It cannot influence online decisions unless a routine-task audit deliberately withholds protection and reveals that label.

## Observability modes

| Mode | Online label | Main weakness |
|---|---|---|
| Outcome-only | Protected final miss | Successful protection masks primary failure |
| Component telemetry | Primary radio/edge failures when available | Dropout and attribution-to-action mismatch |
| Audit feedback | Protected labels plus sparse unprotected routine labels | Audit intervention can harm routine tasks |
| Hybrid | Telemetry first; routine audits only on dropout | More complex and still heuristic |
| Oracle components | Synthetic component probabilities | Diagnostic only; not deployable |

## Safety guard

Audits are permitted only for the routine class. Important and critical tasks keep normal protection eligibility. The simulator reports `critical_audit_fraction`, and automated tests require it to remain exactly zero.

## Interpretation boundary

The paired potential outcomes make masking measurable inside the simulator, but they do not identify real-world counterfactuals. v3.5 tests observability failure modes; it does not provide a causal estimator, exploration theorem, or certified safety constraint.
