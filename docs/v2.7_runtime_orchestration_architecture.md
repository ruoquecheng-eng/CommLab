## Design principle

v2.7 treats several previously static configuration choices as runtime decisions. Each controller is deliberately simple enough to inspect mathematically. The goal is to expose failure modes and Pareto structure before introducing black-box optimization.

## Slow and fast timescales

- **Slow:** edge model-cache replacement, long-term carbon/fairness weighting.
- **Medium:** FL model keyframes and client participation.
- **Fast:** per-slot inference chunk scheduling and multicast repair.

This separation makes it possible to ask whether an optimization at one timescale creates stale state, statistical bias, churn, queue fragmentation, or excessive repair traffic at another.
