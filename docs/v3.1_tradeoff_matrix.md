# CommLab v3.1 Trade-off Matrix

| Research question | Methods | Primary metrics | Key caution |
|---|---|---|---|
| Should wireless feedback prioritize freshness/error or safety proximity? | Max-Age, Max-Error, Safety-Value | safety violation, mean/P95 control cost, age | not a formal barrier-function controller |
| How should inference adapt when radio and compute share a deadline? | fixed light, fixed deep, adaptive bits+depth | on-time accuracy, miss rate, bits, depth, latency | analytic task model, not measured DNN |
| When is checkpointing worth its overhead? | restart, checkpoint migration, dual execution | mean/P95 latency, deadline miss, traffic, compute load | synthetic failure/recovery timings |
| Which AI models deserve scarce replicas? | popularity, task-risk-aware placement | raw outage, task-weighted outage, utility, storage | simple independent node failures |
| Is uniform low-precision state transport task-optimal? | round robin, all-low, value-component | mean/P95 control cost, payload, delivery | linear 3-D state and heuristic value score |

## Recommended narrative

The strongest v3.1 story is not that every new controller dominates. Instead, different objectives produce different operating regions: checkpointing is wasteful at very low failure rates; adaptive inference is most useful before high-SNR fixed deep inference becomes feasible; protecting critical models can worsen raw outage counts; safety-bound scheduling trades average cost against explicit state-constraint risk; and component-level state value can dominate uniform fidelity.
