# v2.9 State-Value Control Architecture

```text
                         ┌───────────────────────────────────────────┐
                         │          Application / Physical State     │
                         │ tasks, model versions, batteries, plants │
                         └───────────────────┬───────────────────────┘
                                             │
                         value / urgency / uncertainty / control cost
                                             │
       ┌─────────────────────────────────────┼─────────────────────────────────────┐
       │                                     │                                     │
┌──────▼────────┐                    ┌───────▼─────────┐                  ┌────────▼────────┐
│ Model state   │                    │ FL client state │                  │ Physical-loop   │
│ repair/cache  │                    │ debt/battery/CO2│                  │ state estimate  │
└──────┬────────┘                    └───────┬─────────┘                  └────────┬────────┘
       │                                     │                                     │
 repair/refresh admission              client scheduling                   sensor scheduling
       │                                     │                                     │
       └──────────────────────┬──────────────┴──────────────────────┬──────────────┘
                              │                                     │
                     Wireless / backhaul resource           Digital-twin predictor
                              │                                     │
                    success, queueing, outage                prefetch confidence
                              │                                     │
                              └──────────────┬──────────────────────┘
                                             │
                                   downstream task/control utility
```

## Design principle
v2.9 treats *state value* rather than raw state age as the control variable. A model update, client round, prefetch, or sensor packet matters only through the downstream task it changes. This makes deliberately visible several metric mismatches:

- model age vs current task demand;
- requested freshness vs backhaul congestion;
- carbon minimization vs learning fairness/energy feasibility;
- digital-twin prediction gain vs speculative cache churn;
- information age vs closed-loop physical control cost.

## Boundaries
The architecture is intentionally modular and analytically transparent. It does not contain a general-purpose RL controller, industrial plant model, production model-serving system, or formal stochastic-optimal control proof.
